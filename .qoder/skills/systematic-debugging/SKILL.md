# 系统化调试

结构化的 4 阶段方法来发现和修复 bug。绝不猜测 — 遵循流程。

## 阶段 1：观察

1. **复现** 问题，确保一致
2. **收集证据**：错误消息、日志、堆栈跟踪
3. **识别边界**：什么工作 vs 什么不工作
4. **检查最近变更**：自上次正常工作以来改变了什么？

## 阶段 2：假设

1. 形成 2-3 个关于根因的假设
2. 按可能性和验证难易程度排序
3. 对每个假设，定义什么证据能确认/反驳它

## 阶段 3：验证

1. 系统化地测试每个假设
2. 从最可能的假设开始
3. 用证据，而非直觉
4. 如果都不匹配，回到阶段 1 收集更多证据

## 阶段 4：修复

1. 编写复现 bug 的测试（RED）
2. 修复根因（而非症状）
3. 验证测试通过（GREEN）
4. 检查相关问题（纵深防御）
5. 运行完整测试套件 — 无回归

## 规则

- **绝不** 在不理解根因的情况下修复
- **绝不** 应用无法验证的修复
- **绝不** 跳过编写回归测试
- **绝不** 修复症状 — 修复原因

## 调试技术

- **二分搜索**：通过减半搜索空间来缩小范围
- **添加日志**：为代码添加 instrumentation 来跟踪执行
- **阅读错误**：真正地、完整地、仔细地阅读它
- **检查假设**：你确定什么？无论如何都要验证
- **解释它**：大声描述问题 — 通常会揭示答案
