# 执行计划

系统化地逐任务执行实施计划，每步都有验证。

## 何时使用

- 当 `docs/plans/` 中存在已批准的实施计划时
- 在开发工作流的实施阶段

## 流程

### 开始前
1. 从 `docs/plans/` 读取完整计划
2. 从 `docs/designs/` 读取设计文档
3. 从 `openspec/specs/` 读取相关规格
4. 确保所有测试当前通过（干净的基线）

### 执行循环

对每个任务：

1. **阅读** 任务详情（文件、步骤、验证）
2. **编写** 失败测试优先（RED）
3. **运行** 测试 — 确认它失败
4. **编写** 最小实现（GREEN）
5. **运行** 测试 — 确认它通过
6. **重构** 如需要 — 确认测试仍然通过
7. **提交** 消息：`feat: <任务描述>`
8. **更新** 计划中的任务状态：`[x]`

### 检查点

在计划定义的每个检查点：
- 停止并审查进度
- 运行完整测试套件
- 验证与设计文档的一致性
- 向用户报告状态
- 获得批准后继续

### 完成

所有任务完成后：
1. 运行完整测试套件 — 必须全部通过
2. 对照计划审查所有变更
3. 验证每个规格需求已满足
4. 调用 `requesting-code-review` 技能
5. 批准后，调用 `verification-before-completion`

## 规则

- 绝不跳过任务
- 绝不跳过验证
- 绝不在测试之前编写实现
- 在检查点停止并报告进度
- 如果任务验证失败，调试后再继续
