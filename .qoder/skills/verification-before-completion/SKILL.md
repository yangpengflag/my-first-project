# 完成前验证

在宣布成功之前确保工作真正完成。证据胜于声明。

## 何时使用

- 在宣布任务完成之前
- 在宣布变更/功能完成之前
- 在合并或部署之前
- 在调试之后 — 验证修复确实有效

## 验证清单

### 功能验证
- [ ] 所有规格需求已满足
- [ ] 所有计划任务已完成
- [ ] 所有测试通过（单元、集成、端到端）
- [ ] 现有功能无回归
- [ ] 边界情况已处理

### 质量验证
- [ ] 代码审查已完成（如适用）
- [ ] 无 lint 错误或警告
- [ ] 无未跟踪的 TODO/FIXME
- [ ] 文档已更新（如适用）

### 规格合规
- [ ] 重读原始规格/需求
- [ ] 对照实现验证每个需求
- [ ] 确认验收标准已满足

### 证据收集
- [ ] 显示全部通过的测试输出
- [ ] 证明功能的截图或日志（如 UI）
- [ ] 性能指标（如性能敏感）

## 规则

- **绝不** 在不运行测试的情况下宣布完成
- **绝不** 假设它有效因为"应该有效" — 证明它
- **绝不** 跳过规格合规检查
- 始终提供完成的证据

## 完成报告格式

```markdown
## 完成报告

**变更：** <变更名称>
**状态：** ✅ 完成

### 验证证据
- 测试：X 通过，0 失败
- 规格需求：X/Y 已满足
- 审查：由 <审查者> 批准

### 交付内容
- 变更摘要
- 修改/创建的文件

### 后续步骤
- 在 OpenSpec 中归档变更
- 如需要更新主规格
```
