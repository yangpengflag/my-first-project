# OpenSpec 应用变更

## 概述

实施已批准的变更，将增量规格合并到主规格中。

**核心原则：** 严格按照批准的提案实施。

## 何时使用

- 变更提案已获批准
- 准备实施变更
- 需要更新主规格

## 前置条件

- [ ] 提案已获批准
- [ ] 增量规格已编写
- [ ] 实施计划已制定

## 流程

### 1. 审查提案

```bash
# 查看提案
cat openspec/changes/<change-name>/proposal.md

# 查看增量规格
ls openspec/changes/<change-name>/specs/
```

### 2. 实施变更

按照提案和规格实施代码变更：
- 遵循 TDD 流程
- 保持测试通过
- 记录实施决策

### 3. 合并规格

将增量规格合并到主规格：

```bash
# 编辑主规格
# 将增量内容合并到 openspec/specs/<domain>/spec.md
```

### 4. 验证

- [ ] 所有测试通过
- [ ] 规格已更新
- [ ] 文档已更新（如需要）

### 5. 标记完成

更新提案状态：

```markdown
## 状态
已完成
```

## 注意事项

- 不要偏离批准的提案
- 如需重大变更，重新提案
- 保持规格与代码同步
