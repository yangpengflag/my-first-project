# 使用 Superpowers 技能

<EXTREMELY-IMPORTANT>
如果你有 1% 的把握某个技能可能适用，你绝对必须调用该技能。

如果技能适用于你的任务，你没有选择。你必须使用它。

这没有商量余地。你不能找借口跳过。
</EXTREMELY-IMPORTANT>

## 规则

**在任何回应或行动之前调用相关或请求的技能** — 包括澄清问题、探索代码库或检查文件。如果最终不适用，可以不用。

**进入计划模式前：** 如果还没头脑风暴，先调用 brainstorming 技能。

然后宣布"使用 [技能] 来 [目的]"并严格按照技能执行。如果有检查清单，为每项创建待办。

## 技能优先级

多个技能适用时，流程技能优先 — 它们设定方法，然后实施技能执行。

- "我们来构建 X" → 先 brainstorming，再实施技能
- "修复这个 bug" → 先 systematic-debugging，再领域技能

## 红旗信号

这些想法意味着停止 — 你在找借口：

| 想法 | 真相 |
|------|------|
| "这只是个简单问题" | 问题也是任务。检查技能。 |
| "我需要更多上下文" | 技能检查在澄清问题之前。 |
| "让我先探索代码库" | 技能告诉你如何探索。先检查。 |
| "我可以快速检查 git/文件" | 文件缺乏对话上下文。检查技能。 |
| "让我先收集信息" | 技能告诉你如何收集信息。 |
| "这不需要正式技能" | 有技能就用。 |
| "我记得这个技能" | 技能会演进。读当前版本。 |
| "这不算任务" | 行动 = 任务。检查技能。 |
| "技能杀鸡用牛刀" | 简单事会变复杂。用它。 |
| "我就先做这一件事" | 做任何事之前先检查。 |
| "这感觉很有成效" | 无纪律的行动浪费时间。技能防止这点。 |
| "我知道那是什么意思" | 知道概念 ≠ 使用技能。调用它。 |

## 用户指令

用户指令（AGENTS.md、直接请求等）优先于技能，技能优先于默认行为。只有当用户明确告诉你跳过时，才跳过技能流程。
