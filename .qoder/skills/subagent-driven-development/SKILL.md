# 子代理驱动开发

## 概述

将复杂开发任务分解为独立的子任务，分配给多个子代理并行执行。

**核心原则：** 任务隔离、并行执行、集中整合。

## 何时使用

**适用场景：**
- 大型重构需要多文件修改
- 多个独立功能可以同时开发
- 复杂 bug 涉及多个子系统
- 需要并行测试多个方案

**不适用场景：**
- 任务有强顺序依赖
- 子任务共享大量状态
- 任务太小不值得分解

## 流程

### 1. 任务分解

将大任务分解为独立的子任务：
- 每个子任务有明确的输入/输出
- 子任务之间无依赖或依赖最小
- 每个子任务可在隔离上下文中完成

### 2. 定义子代理指令

每个子代理需要：
- **明确范围：** 具体要做什么
- **上下文：** 所需的所有信息
- **约束：** 不能做什么
- **输出格式：** 期望的返回格式

### 3. 并行调度

同时启动所有子代理：
```
子代理 1: [任务描述]
子代理 2: [任务描述]
子代理 3: [任务描述]
```

### 4. 监控进度

- 跟踪每个子代理的状态
- 识别卡住的代理
- 必要时重新分配任务

### 5. 整合结果

所有代理完成后：
- 收集所有输出
- 解决冲突
- 整合变更
- 运行完整测试

## 任务分解原则

### 好的分解

| 特征 | 说明 |
|------|------|
| 独立性 | 子任务可并行执行 |
| 明确边界 | 范围清晰不重叠 |
| 可验证 | 每个子任务有明确的完成标准 |
| 平衡 | 工作量大致相等 |

### 坏的分解

- 子任务有循环依赖
- 范围模糊重叠
- 工作量严重不均
- 需要频繁协调

## 子代理指令模板

```markdown
任务：[具体任务描述]

上下文：
- [相关背景信息]
- [文件路径]
- [约束条件]

要求：
1. [具体要求 1]
2. [具体要求 2]

输出：
- [期望的输出格式]

约束：
- [不能做的事情]
```

## 常见问题

| 问题 | 解决方案 |
|------|----------|
| 子代理卡住 | 提供更明确的指令 |
| 输出冲突 | 预先定义接口契约 |
| 质量不一 | 添加质量检查清单 |
| 进度不同步 | 设置检查点 |

## 验证清单

- [ ] 所有子任务已完成
- [ ] 输出格式符合要求
- [ ] 无冲突
- [ ] 完整测试通过
- [ ] 代码风格一致
