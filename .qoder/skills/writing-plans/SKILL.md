# 编写实施计划

将已批准的设计转化为详细的、逐步的实施计划，可由 AI 代理或人类开发者执行。

## 何时使用

- 在 `brainstorming` 技能产生已批准的设计之后
- 当你需要将大变更分解为可管理的任务时
- 在任何实施工作开始之前

## 计划结构

每个计划应保存到 `docs/plans/YYYY-MM-DD-<主题>-plan.md` 并包含：

### 任务格式

```markdown
## 任务 N：<任务标题>

**文件：**
- `src/path/to/file.ts` — 创建/修改

**步骤：**
1. 要采取的确切行动
2. 要编写的代码（如适用）
3. 要添加的测试

**验证：**
- [ ] 测试通过：`npm test -- --grep "测试名称"`
- [ ] 无 lint 错误
- [ ] 规格需求已满足

**预计时间：** 2-5 分钟
```

## 指南

1. **粒度**：每个任务应花费 2-5 分钟
2. **完整性**：每个任务都有精确文件路径和验证步骤
3. **顺序**：任务应按依赖排序（基础优先）
4. **TDD**：每个实施任务之前应有对应的测试任务
5. **检查点**：每 5-10 个任务添加审查检查点

## 计划模板

```markdown
# 实施计划：<功能名称>

**设计文档：** `docs/designs/YYYY-MM-DD-<主题>-design.md`
**OpenSpec 变更：** `openspec/changes/<变更名称>/`
**创建日期：** YYYY-MM-DD
**状态：** draft | in-progress | complete

## 任务

### 阶段 1：基础
- [ ] 任务 1：...
- [ ] 任务 2：...

### 阶段 2：核心实施
- [ ] 任务 3：...
- [ ] 任务 4：...

### 阶段 3：集成与测试
- [ ] 任务 5：...

## 检查点
- 任务 2 后：与用户审查基础
- 任务 4 后：审查核心实施
- 任务 5 后：最终验证
```

## 反模式

- ❌ 模糊任务如"实现功能"
- ❌ 没有验证步骤的任务
- ❌ 花费超过 10 分钟的任务
- ❌ 跳过测试任务
- ❌ 无检查点审查
