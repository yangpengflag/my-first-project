# 编码规约

> 基于 Superpowers + OpenSpec 方法论的项目编码规范

## 三条底线，不可违反：

### 1. YAGNI — You Aren't Gonna Need It
- 只写当前 spec 需要的代码。
- 不预留"将来可能用到"的参数、接口、抽象。
- 不重构未被要求修改的代码。

### 2. DRY — Don't Repeat Yourself
- 出现第三次相同模式才抽。第一次照写，第二次容忍，第三次提炼。
- 不要为了消除两处微小重复而引入新抽象层。

### 3. TDD — Test-Driven Development
- 严格遵守 RED → GREEN → REFACTOR：
  1. 先写一个**会失败**的测试，亲眼看它失败。
  2. 写**最小**实现让它通过。
  3. 在绿灯下重构。
- 实现前写的代码若没对应失败测试，必须删掉重来。

**铁律：没有失败测试，就不写生产代码。**

## 注释

- 仅在意图无法从代码本身看出时才加注释。
- 优先短注释，避免大段块注释。
- 不写"这是干什么的"流水账，写"为什么这么干"。

## 测试规范

- 一个测试只测一件事。名字里有"and"？拆开它。
- 名字描述行为，而非实现。
- 用真实代码，除非万不得已才用 mock。
- 测试只放在测试工具类中，不混入生产类。

## 常见借口与真相

| 借口 | 真相 |
|------|------|
| "太简单了不用测试" | 简单代码也会坏。测试只需 30 秒。 |
| "我之后再测" | 之后再测 = 永远不测。先测才能证明它能捕获 bug。 |
| "我已经手动测过了" | 手动测试无法覆盖边界情况，也无法回归验证。 |
| "删掉重做太浪费时间" |  sunk cost fallacy — 时间已经花了。重写才有高信心。 |
| "保留作参考，先写测试" | 你会"适配"它。那就是后测。删掉意味着删掉。 |

## 红旗信号 — 停下来重来

- 先写代码后写测试
- 测试写完就通过
- 无法解释测试为何失败
- 测试是"之后再补"的
- 合理化"就这一次"

**以上所有意味着：删掉代码，用 TDD 重来。**

## 调试集成

发现 bug？先写一个复现它的失败测试，再走 TDD 循环。
测试证明修复有效，并防止回归。

**永远不要不写测试就修 bug。**
